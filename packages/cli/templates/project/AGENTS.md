# Vibecloud project

Use the project-local Vibecloud skill at `.agents/skills/vibecloud/SKILL.md`
when adding, changing, validating, deploying, or removing application resources.
Use the project-local Gravity UI skill at `.agents/skills/gravity-ui/SKILL.md`
when creating or changing a Vite interface.

Install `@vibecloud/*` from Verdaccio or the project's configured
npm-compatible registry. Preserve `.npmrc` and registry environment overrides;
the CLI, runtime packages, and development container must use the same release
source. Check that registry and the exact published version on a package 404.
Do not replace registry dependencies with tarball or workspace overrides.

Use `pnpm dev` for local development and `pnpm push` for deployment within the
user's requested scope. A separate Terraform plan is not a normal prerequisite.
Choose YDB and Better Auth when the application needs storage or accounts;
custom AI handlers can use `@vibecloud/ai` without either.

Keep `build.ts` and `vite.config.ts` as thin entrypoints into the installed CLI.
Preserve authored scripts and build hooks when adding resources. Generated Terraform
and Compose files refresh from that release when their managed contents are unchanged.
Customize with separate `.tf` files and `infra/local.override.yaml`; remove a managed
marker only when intentionally taking ownership of that file. Never store authored
files in `dist`, `.vibecloud/builds/`, or `infra/.packages/`.

Use `ai.images.generate()` for Alice AI ART and read the completed image with
`requireAIStudioImage()`. The retired YandexART API and operation polling are no
longer supported. Keep prompts within 500 characters and use the image template's
synchronous response contract; see the project skill's AI reference.

Return image metadata `{ key, url, contentType, sizeBytes }` after uploading bytes
with `@vibecloud/storage`. Render the URL directly. The image template creates a
public bucket by default; signing, private access, Better Auth, and YDB are opt-in.
Use the reserved `/_vibecloud/` namespace only through Vibecloud's runtime.

`pnpm push` uploads immutable assets and tagged function versions before switching
the gateway. Keep migrations and APIs compatible with the preceding release.
Asset downloads follow the declared gateway routes, including retained releases.
Asset and bucket renames preserve retained release URLs and local media identities;
commit `.vibecloud/local-buckets.json` when generated by a bucket rename.
Database renames preserve local service names and volumes; commit
`.vibecloud/local-databases.json` when generated too.
Custom asset builders must honor `VIBECLOUD_ASSET_BASE` for asset references.
Multiple checkouts deploying to the same app must share a Terraform backend and
workspace with state locking. If another deployment makes a push's internal plan
stale, rerun `pnpm push` after it finishes.

Use the printed local URL; Docker resources are scoped to this checkout's path.
`pnpm vibecloud down` stops the host controller and pending startup/restarts before
removing containers/network, preserving data. Only one dev controller runs per checkout. When data
removal is requested, add `--volumes --confirm delete-local:<application-name>`.
Commit `.vibecloud/generated-guidance.json` so untouched generated instructions can
refresh safely, including removal of unchanged files retired from the package.
Reconcile warnings about customized or untracked guidance explicitly.

Local development requires OrbStack. Use the printed `.orb.local` URLs; do not add
host-port allocation or a separate Vite startup path. Terraform owns cloud resource
planning, dependencies, state and locking. Keep `pnpm push` as the deployment entrypoint;
do not build a parallel resource planner or reconciliation loop.

Function `kind` and `features` are explicit runtime policy; templates are scaffolding
provenance. Keep policy aligned with handler changes. Source edit recovery does not
roll back cloud operations. Serialize whole-folder deletion with other checkouts.

Run project management commands on the host. The development container owns its
processes and a private `app-runtime` build volume at `/vibecloud-runtime`; host
`dist` and deployment snapshots remain independent. This avoids sharing build locks
between the host and OrbStack kernels.

For architecture or recovery changes, read the installed CLI's
`node_modules/@vibecloud/cli/ARCHITECTURE.md`. Keep normal application authoring on
the logical resource commands. A deletion request accepted with `0s` can remain
pending while YC cleans up; preserve its receipt and report the observed status.
