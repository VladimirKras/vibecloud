# `@vibecloud/codex-skill-init`

Installs the global `vibecloud-init` Codex skill. The skill recognizes requests
to create a new application, initializes it with Vibecloud, and then hands work
off to the project-local `vibecloud` skill generated by the CLI. Generated applications
use thin build/Vite entrypoints and managed infrastructure templates that follow
the installed release; app customizations belong in override files.

Use Verdaccio or the configured npm-compatible registry hosting Vibecloud;
the package is not assumed to be available on public npm. With that registry
selected through `.npmrc` or the package-manager environment, run
`pnpm dlx @vibecloud/codex-skill-init@<published-version> install`.

For source development, run `node packages/codex-skill-init/bin/install.ts
install` from the Vibecloud workspace root. This installs the current guidance
without publishing packages. The skill then prefers the workspace's
`pnpm local:init` workflow when creating an app against local Verdaccio, and
preserves configured registry settings for other npm-compatible registries.

The default destination is `$CODEX_HOME/skills/vibecloud-init`, or
`~/.codex/skills/vibecloud-init` when `CODEX_HOME` is unset. Repeating the
installation is a no-op. A managed, unmodified older copy is upgraded
automatically. The installer refuses to overwrite an unmanaged or edited copy;
pass `--force` to preserve that copy as a timestamped backup and install the
published skill.

Use `--codex-home <directory>` to select a different Codex home.

Image-template guidance uses public Object Storage URLs by default; private access
and signing remain optional. Project skills explain release activation, checkout
scoped local teardown, and hash-based refresh of generated guidance.

Generated applications use `pnpm dev` with OrbStack and printed `.orb.local` URLs; no host-port allocation is needed.

The installed CLI includes `ARCHITECTURE.md` for architecture and recovery work;
normal application authoring remains with the generated project skill. Deletion
submission and provider-confirmed completion are separate outcomes.
